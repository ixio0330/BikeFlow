# BikeFlow

> 서울 공공자전거(따릉이) 대여소의 실시간 현황을 지도에 시각화하고, 가까운 미래의 자전거 부족·거치 공간 부족 가능성을 예측하는 위치 기반 서비스

## 프로젝트 소개

BikeFlow는 서울시 공공자전거 데이터를 활용해 대여소별 위치와 자전거 재고를 실시간으로 보여주는 스마트시티 프로젝트입니다.

사용자는 지도에서 주변 대여소의 현재 상태를 확인할 수 있으며, 과거의 대여·반납 패턴을 바탕으로 특정 대여소가 곧 비거나 가득 찰 가능성도 미리 파악할 수 있습니다. 대규모 공간 데이터의 효율적인 시각화부터 실시간 데이터 파이프라인, 간단한 수요 예측 모델, 클라우드 배포까지 하나의 서비스 안에서 구현하는 것을 목표로 합니다.

## 핵심 목표

- 서울시 공공데이터 API를 활용한 실시간 대여소 정보 수집
- 지도 기반의 직관적인 대여 가능 자전거 및 거치 공간 현황 제공
- 수천 개 대여소를 효율적으로 렌더링하는 공간 데이터 처리
- 과거 이용 패턴을 활용한 단기 재고 상태 예측
- GCP 기반 서버리스 컨테이너 아키텍처와 CI/CD 파이프라인 구축

## 주요 기능

### 실시간 대여소 현황

- 대여소의 위치, 대여 가능 자전거 수, 거치 가능 공간 표시
- 잔여 자전거 수 또는 대여 가능 비율에 따른 마커 색상 구분
- 일정 주기로 데이터를 갱신해 최신 상태 유지

### 지도 시각화

- MapLibre GL JS 기반 인터랙티브 지도 제공
- OpenFreeMap에서 지도 스타일과 타일을 제공받아 기본 지도 표시
- GeoJSON 형식으로 대여소 공간 데이터 관리
- 지도 이동 및 확대 수준에 맞춘 데이터 표시

### 대규모 마커 클러스터링

- `supercluster`를 사용해 수천 개의 대여소 마커를 클러스터링
- 줌 레벨과 화면 영역에 필요한 데이터만 렌더링
- 마커 밀집 지역의 가독성과 지도 조작 성능 개선

### 대여소 상태 예측

- 과거 시간대별 대여·반납 패턴을 학습 데이터로 활용
- 가까운 미래에 자전거가 부족해질 대여소 예측
- 가까운 미래에 거치 공간이 부족해질 대여소 예측
- 예측 결과와 신뢰도 또는 위험 단계를 지도에 시각화

| 경험 영역                            | BikeFlow에서 구현하는 내용                                                        | 결과물로 보여줄 수 있는 역량                               |
| ------------------------------------ | --------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 자율주행·스마트시티·위치 기반 서비스 | 서울시 공공데이터 API를 연동해 대여소별 실시간 위치와 재고 정보 제공              | 도시 이동 데이터를 활용한 위치 기반 서비스 설계 경험       |
| 대규모 데이터 처리 및 분석           | 수천 개 대여소 데이터를 `supercluster`로 클러스터링하고 화면 영역 중심으로 렌더링 | 공간 데이터 처리, 프런트엔드 성능 최적화, 데이터 분석 경험 |
| 클라우드 플랫폼                      | Cloud Run, Pub/Sub, BigQuery를 활용한 수집·저장·조회 API 및 자동 배포 구성        | 서버리스 컨테이너, 이벤트 처리, 데이터 분석, CI/CD 경험    |
| 머신러닝 및 AI 알고리즘              | 과거 대여·반납 패턴을 기반으로 단기 재고 상태를 예측하는 모델 구축                | 특성 설계, 모델 학습·평가, 추론 결과의 서비스 적용 경험    |
| GIS                                  | MapLibre GL JS와 GeoJSON을 활용한 지도 시각화 및 좌표 데이터 처리                 | 공간 데이터 모델링, 좌표계 이해, GIS 기반 UI 구현 경험     |

## 기술 스택

| ------------------ | --------------------------------------------------------- |

## 시스템 구성

```text
서울시 공공데이터 API
        │
        ▼
Cloud Scheduler ──────► Cloud Run / NestJS
                          수집·정제·조회 API
                                │
                                ▼
                         Pub/Sub ──────► BigQuery
                         이벤트 전달      이력·분석
        │
        ▼
실시간 조회 API / SSE
        │
        ▼
웹 클라이언트
MapLibre GL JS + OpenFreeMap + GeoJSON + supercluster
        │
        ▼
현재 상태 및 단기 예측 결과 시각화
```

### 지도 구성요소와 역할

BikeFlow의 지도는 하나의 통합 유료 서비스 대신 역할별 구성요소를 조합합니다.

| 구성요소       | 역할                                                      |
| -------------- | --------------------------------------------------------- |
| MapLibre GL JS | 브라우저에서 지도를 그리고 이동·확대·축소를 처리하는 엔진 |
| OpenFreeMap    | 도로, 건물 등이 포함된 지도 스타일과 타일 제공            |
| GeoJSON        | 따릉이 대여소의 위치와 상태를 표현하는 공간 데이터 형식   |
| supercluster   | 줌 수준에 따라 가까운 대여소 마커를 묶어 표시             |

MapLibre GL JS는 BSD 3-Clause 라이선스의 오픈소스 렌더링 라이브러리입니다. 지도 데이터는 라이브러리에 포함되지 않으므로 OpenFreeMap을 별도로 연결합니다. 향후 장소·주소 검색이나 자전거 길찾기가 필요해지면 지오코딩 및 라우팅 서비스를 별도로 선정합니다.

## 단계별 구현 계획

### 1. 실시간 데이터 연동

- 서울 열린데이터광장에서 인증키 발급
- 공공자전거 대여소 실시간 정보 API 연동
- API 응답을 서비스 내부 데이터 모델로 정규화
- 오류, 호출 제한, 데이터 누락에 대한 예외 처리

**완료 기준:** 실제 대여소의 위치와 재고 정보를 안정적으로 조회할 수 있다.

### 2. 대여소 지도 시각화

- MapLibre GL JS를 초기화하고 OpenFreeMap 스타일 연결
- 대여소 데이터를 GeoJSON으로 변환
- 잔여 자전거 수 또는 대여 가능 비율에 따라 마커 색상 구분
- 마커 선택 시 상세 정보를 보여주는 팝업 구현

**완료 기준:** 지도에서 대여소별 실시간 상태를 직관적으로 확인할 수 있다.

### 3. 마커 클러스터링 및 성능 최적화

- `supercluster`로 줌 레벨별 클러스터 생성
- 현재 지도 영역에 포함된 대여소만 조회 및 렌더링
- 확대 시 클러스터를 개별 대여소 마커로 전환
- 렌더링 시간과 지도 조작 성능 측정

**완료 기준:** 수천 개 대여소가 표시된 상태에서도 지도를 부드럽게 탐색할 수 있다.

### 4. 실시간 갱신 파이프라인

- Cloud Scheduler가 Cloud Run의 수집 엔드포인트를 주기적으로 호출
- Pub/Sub으로 저장·분석 작업을 분리하고 BigQuery에 이력 적재
- 초기 버전은 폴링으로 구현하고, 필요성과 운영 비용을 검토해 SSE 적용
- 오래된 데이터와 최신 데이터의 상태를 클라이언트에 명시

**완료 기준:** 사용자가 새로고침하지 않아도 대여소 상태가 일정 주기로 갱신된다.

### 5. 단기 재고 예측 모델

- 과거 대여·반납 데이터를 대여소 및 시간 단위로 집계
- 시간대, 요일, 공휴일, 최근 재고 변화량 등의 특성 생성
- 기준 모델과 간단한 회귀·분류 모델의 성능 비교
- 대여소가 곧 비거나 가득 찰 위험을 단계별로 표시

**완료 기준:** 현재 상태만 보여주는 기준 방식보다 나은 예측 성능을 측정 지표로 확인하고, 결과를 지도에 제공한다.

### 6. 배포 및 CI/CD

- Vite로 빌드한 React 정적 파일을 NestJS가 서빙하도록 구성
- 웹과 `/api/v1` API를 하나의 Docker 이미지로 Cloud Run에 배포
- GitHub Actions를 통한 테스트와 배포 자동화
- 로그, 오류 추적, 핵심 성능 지표를 확인할 수 있는 운영 환경 구성

**완료 기준:** 메인 브랜치 변경 사항이 검증 과정을 거쳐 자동으로 배포된다.

## 예측 모델 방향

첫 번째 버전에서는 복잡한 딥러닝 모델보다 결과를 설명하고 개선하기 쉬운 기준 모델부터 시작합니다.

- **예측 대상:** 향후 일정 시간 내 자전거 부족 또는 거치 공간 부족 여부
- **주요 특성:** 대여소 ID, 시간대, 요일, 계절, 최근 재고, 최근 변화량, 과거 동일 시간대 평균
- **기준 모델:** 현재 재고 유지, 과거 동일 시간대 평균
- **후보 모델:** 로지스틱 회귀, 트리 기반 분류·회귀 모델
- **평가 지표:** MAE/RMSE 또는 Precision, Recall, F1 Score
- **서비스 표현:** 정상, 주의, 위험 단계와 예측 기준 시각 표시

모델의 복잡도 자체보다 데이터 수집부터 특성 설계, 오프라인 평가, 서비스 추론까지 이어지는 전체 흐름을 완성하는 데 초점을 둡니다.

## 프로젝트를 통해 쌓는 경험

- 공공 교통 데이터를 활용한 스마트시티 및 위치 기반 서비스 설계
- 대규모 공간 데이터의 변환, 클러스터링, 렌더링 최적화
- 서버리스 컨테이너 환경의 데이터 수집, 이벤트 처리, 분석, 배포 경험
- 실제 시계열 데이터에 대한 탐색, 특성 설계, 모델 평가 경험
- 지도 UI와 공간 데이터 형식을 다루는 GIS 실무 경험
- 데이터 최신성, 장애 대응, 관측 가능성을 고려한 운영 경험

## 확장 로드맵: 실시간 버스 위치 및 혼잡도 예측

BikeFlow를 완주한 뒤에는 서비스를 직접 확장하는 대신, 별도 프로젝트로 **버스 실시간 위치와 혼잡도 예측 서비스**를 구축합니다.

자전거 대여소는 위치가 고정된 단일 공간 객체를 중심으로 하지만, 버스 서비스는 노선·정류소·차량이 연결되는 다대다 구조를 다룹니다. 이를 통해 다음 단계의 복잡도를 경험할 수 있습니다.

- 이동하는 차량의 실시간 위치 추적
- 노선, 정류소, 차량 간 관계 모델링
- 도착 예정 시간 및 구간별 혼잡도 예측
- 지도 위 이동 객체의 효율적인 갱신과 시각화
- 더 복잡한 스트리밍 데이터 파이프라인 설계

```text
BikeFlow
고정된 대여소 + 실시간 재고 + 단기 수요 예측
        │
        ▼
별도 버스 프로젝트
이동 차량 + 노선·정류소 관계 + 도착·혼잡도 예측
```

이 로드맵은 하나의 서비스를 무리하게 확장하기보다, GIS·실시간 데이터·예측·클라우드 역량을 프로젝트 단위로 단계적으로 심화하는 것을 목표로 합니다.
